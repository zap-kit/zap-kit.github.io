Why Zap

  • Made for agents. Fewer tokens per program, errors that say how to fix them.
  • Efficient by design. Lean native code, for weaker devices too; games recompiled or decompiled into native ports are its proof of concept.
  • Safe with no ceremony. Memory is checked at compile time with nothing written for it: no lifetimes, no annotations, no garbage collector.
  • Built for data. Parallel loops, vectors and tensors are the language itself, not C swept under the rug.
  • CPU and GPU alike. A shader is Zap, under the same types and rules; the engine is built on it.
  • One tool, no setup. zap builds, runs, tests, formats and documents. Straight from code to machine code, no LLVM in between: every optimization in reach.
